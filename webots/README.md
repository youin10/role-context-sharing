# Webots context-sharing evaluation

Closed-loop evaluation of conditional context sharing in a Webots R2025a world. Robot locations, zone congestion, observed stop durations and cargo custody are derived from the running simulation and reported as ontology predicates. Consumers receive `assert`, `update` and `retract` notifications through the proposed derivation (D), explicit subscription rules (A), or the same rules generated by a helper (H). A shared routine turns the consumer's view into hold, release or detour decisions, and those decisions move robots in the simulator.

Webots runs in a container. Motion is a kinematic position update and all robot classes share the same motion. This package does not evaluate sensing, collision avoidance, safety, physical scalability or latency. See `DESIGN.md` and `RESULTS.md`.

## Requirements

Docker with Compose and linux/amd64 emulation on other architectures, Python 3 (recorded with 3.14.7), and network access for the first image build. No GPU and no local Webots installation are needed.

## Setup

```bash
./setup.sh
```

This checks the core archive, extracts it to `core/`, creates `.venv/` and builds the image `wcs-webots:R2025a`.

## Run

```bash
.venv/bin/python -B tools/check_static.py
.venv/bin/python -B tools/run_one.py --scenario TR1 --arm D --rep 1 --label check
.venv/bin/python -B tools/judge.py records/check/TR1-D-1
.venv/bin/python -B tools/run_matrix.py --label <label>
.venv/bin/python -B tools/run_matrix.py --label <label> --negative
.venv/bin/python -B tools/summarize.py <label>
.venv/bin/python -B tools/mutate_nc.py <label>
```

The full matrix (11 scenarios, 3 arms, 3 repetitions) took about 23 minutes with three parallel jobs on the recorded host. Each run starts a fresh Compose project `wcs-<label>-<run>` and removes that project on exit. MQTT binds to `127.0.0.1` from port 18883 upward (`WCS_MQTT_PORT`). Existing record directories are never overwritten. A rebuilt image can have a different ID; the recorded IDs are in each run's `manifest.json`.

`tools/build_a_rules.py` regenerates the helper arm's rules. `tools/freeze_source.py` writes the source archive.

## Time

`t_sim` is Webots simulation time from the observer. `t_wall` is seconds since the driver started. Scenario steps advance on observed events. Latency is not an outcome of this experiment.
